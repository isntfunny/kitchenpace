# Bring! Implementation Plan

> **For agentic workers:** Use executing-plans to implement task by task. User explicitly requested implementation in this session.

**Goal:** Connect Bring accounts and manage shopping lists and recipe ingredient transfers in KochTakt.
**Architecture:** Server-only credential storage and service, a checked REST v2 adapter, authenticated server actions, shared connection/transfer UI. Bring is the source of truth.
**Tech Stack:** Next.js, Prisma/PostgreSQL, Zod, Node crypto, native fetch, Radix, Panda CSS, node:test via tsx.
**Spec:** docs/superpowers/specs/2026-10-14-bring-design.md

## Global Constraints

- German UI; semantic Panda tokens; existing auth and UI patterns.
- No credentials in logs/client storage; BRING_ENCRYPTION_KEY via Infisical.
- Existing lists only; no deployment; no use of production accounts for tests.

## Decisions during implementation

- A narrow fetch adapter replaces the reference wrapper to check HTTP failures and enforce timeouts without depending on its unvalidated mutation responses.
- Existing matching items are kept, never automatically summed; users edit quantities explicitly. Concurrent remote household changes cannot be made atomic through the legacy Bring endpoint.
- Pending transfer receipts survive transaction rollback and are not automatically replayed; ambiguity requires inspecting the list before an intentional new transfer.
- Test harness uses esbuild as an explicit dev dependency and the existing Playwright browser library. No app dependencies were added.
